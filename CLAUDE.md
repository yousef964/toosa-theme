# TOOSA theme (toosa.ca): working notes

Shopify theme for TOOSA (Toosa Store Solutions Inc.). Separate business from the Spark sites: never mix repos, colours or content. Always "TOOSA"/"Toosa", never "Tusa".

- Base theme: Refine 4.0.0 (Shopify theme store 2782). Exported 14 Oct 2026 from the live theme "TOOSA Redesign (JD)- New Homepage".
- `main` is connected (Shopify GitHub integration) to an UNPUBLISHED dev theme. Pushes update only that theme. The live theme changes only when the owner clicks Publish in Shopify admin.
- Shopify writes theme-editor changes back to this branch as commits; pull before editing.
- Keep Shopify checkout, payments, orders and customers as they are. No Stripe, no rebuild.
- Third-party app blocks (e.g. Hulk apps) render their own code; style around them, don't edit them.
- Never handle passwords; access keys go in the environment settings, never in chat or in this repo.
- Round 3 (15 Oct 2026, homepage/footer/collections): homepage sections `tx-trust` (UL badge strip under the lineup), `tx-compare` (scorecard with meters that fill on scroll, replaces honest-comparison), `tx-about` (photo + fact tiles), `tx-showroom` (map + icon facts); styles live in `assets/tx.css`. Footer is `sections/tx-footer.liquid` + `assets/tx-footer.css` (loaded on every template from theme.liquid; `footer-group.json` points at it; old `footer.liquid` kept). Collection templates use `tx-c-intro` (H1, lead from the first description paragraph, chips, category tiles) and `tx-c-about` (collection.description styled, CSS-only read-more on phones) with `assets/tx-collection.css`; the product grid and filters are untouched. The theme colours every link with `a:not(.btn-fill)...` at specificity (0,4,1): new sections override it with matching `:not()` chains. UL is claimed only for the TS-20 compressor package (source: the air compressor page copy).
- Round 4 (15 Oct 2026, product pages/collections/contact): all three product templates (`product.json`, `product.tool-storage-template.json`, `product.air-compressors-template.json`) share the `tx-pr-*` sections below the buy box: `tx-pr-overview` (lead from the first description paragraph, icon beats: curated `beat` blocks per product or parsed from the Key Features list / `custom.key_features` metafield / checkmark lines; the full `product.description` stays in the DOM in a collapsed panel), `tx-pr-specs` (sticky fact tiles + tabs: spec rows, what's in the box, documents from `custom.product_pdf_option` and an optional `custom.documents` list), `tx-pr-after` (dark icon strip), `tx-pr-modules` (product cards from handles per family, or the product's own collection as fallback; used twice: modules and related), `tx-pr-faq` (accordion + FAQPage schema). Every block has an `only_for` rule evaluated by `snippets/tx-pr-match.liquid` (handles, `tag:`, `type:`, `template:`, `prefix*`, `!` excludes) so one template serves every product. Styles: `assets/tx-product.css` on top of `tx-pages.css`/`tx-pages.js`, which theme.liquid now loads on product pages too. The old jd-product-tabs / why-toosa / usp / customer-picks / positioning / comparison / forum sections were removed from the templates (files kept). The `tx_builder` section is untouched. Shopify gotchas met: no filters inside `render` arguments, no `assign x = blank`, section/block/preset names max 25 chars; a file that fails once is not retried until it changes again. Collections: `tx-c-intro` defaults to the compact layout (no cover image, range pills with the active range in orange; `layout: tiles` restores the old look); product card tidy rules live at the end of `tx-collection.css`. Contact: `tx-p-contact` renders on a tinted band (`txp-contact-band`) with a map fallback behind the iframe, `tx-p-booking` has a `theme` setting (dark on page.contact.json).
- Footer (17 Oct 2026, Joe: less text): `tx-footer.liquid` menus are `<details class="txf__fold" open>` (open on desktop, collapsed on phones by the inline script; links stay in the HTML), newsletter is one slim row (text setting empty), hours one line, phone + email share a row, colophon shortened. Values live in `footer-group.json`.
